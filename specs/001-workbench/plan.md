# 实施方案

多版本修正：领域层校验 QuickFIX 4.0～4.4，编码入口显式接收版本，接收分帧支持五种版本并在会话层校验字典一致。预览、表单发送、脚本后的托管重编码、自动管理消息、重发/GAPFILL 全部使用连接字典版本。自动登录经过字典 Body，兼容旧字段类型和时间精度；界面显示实际配置版本。加入 QuickFIXGo 标准 40～43 字典及许可证，Go 验证全部版本，Playwright 验证真实 FIX42 导入/表单/预览/登录/心跳/订单及与44共存。不改变 TCP、公用工作区格式及原有选择接口流程。

选择导入修正：Bridge 提供只读 PreviewDictionary，界面展示共用 MessagePicker（默认空选、搜索、多选、全选当前结果、清空），确认时才调用 ImportProtocol(name, xml, types)。应用层对所选类型非空、存在性和去重进行校验，保存完整字典、服务和选中模板；取消或失败无残留。SaveService 无模板选择时直接保存服务，GenerateMessages 补充接收明确选择，已有类型禁选且不覆盖。所有新签名在 Wails 与 HTTP 两个适配中同步，旧导入导出的工作区结构保持兼容。

消息树搜索修正：计算服务与匹配消息的视图，消息命中只渲染匹配项，服务名命中保留其全部消息；原 requestsFor 保持全量，继续用于保存、删除计数及模板用例。搜索词 trim 后统一小写；搜索变化自动展开并回到列表顶部。用真实字典验证 Logon、业务类型、无结果、清除、搜索中保存及刷新恢复。

接收规则绑定修正：Vue 规则选项直接列出 frame 类函数，选择映射为已有的 custom + 函数 ID，内置规则取消关联。管理入口带服务草稿往返，按显式操作绑定。使用 UI 新建函数、绑定、保存和刷新，再由真实 TCP 对端分两次发送 `one!tw`、`o!tail`，验证产生 `one!`、`two!` 两帧，下一次补发 `!` 后才产生 `tail!`。

Wails v2 + Vue 3/TypeScript/Vite + Naive UI + Monaco。Go net 实现通用 TCP，Goja 实现受执行时限约束的脚本，SQLite 存储工作区快照。领域层建模 Service、Request、Function、Dictionary、Message、Event；应用层依赖 Repository 与 SessionFactory 端口，运行时适配器负责连接和 VM，界面适配器调用应用层。

连接有一个读取循环、一个 VM 互斥区与串行写入；读缓冲先按字节分帧后解码。接收函数返回 0 或完整帧的字节数。FIX 使用 BodyLength 确定边界及校验和。定时回调和手动发送使用同一运行时，定时器按名称替换，断开停止。单任务脚本执行时限 1500ms，缓冲、历史、任务数有界。

FIX 字典导入时检查引用和递归，保留顺序与嵌套、枚举、必填。前端依据元数据递归渲染。管理模式自动封装 FIX，原始模式原样发出以支持负例。FIX 模块维护会话状态、心跳、TestRequest、序号缺口/重发；不在 TCP 域写协议判断。

运行时数据与持久配置分开。SQLite 保存用户工作区快照，内存保留有界消息和日志；导出不包含连接和任务。默认用户配置路径由 OS UserConfigDir 解析，可通过 --data-dir 覆盖。根 main 支持桌面和 --web 两种适配，浏览器模式用于测试相同后端。

验收修正：应用层增加 XML 原子导入建服务、按消息类型补全、新建 FIX 服务生成所选模板及指定类型新建消息用例；界面导入后直接打开对应表单，左侧提供补全和服务/消息删除操作。删除以保存成功为界更新界面，服务删除先断开运行时。使用真实 181 消息 XML 和无 Logon 的自定义 XML 验证模板结构、幂等补全、用例内容保留、失败无残留及 SQLite 恢复；Playwright 覆盖入口、删除选中状态和刷新持久化。

手动新建修正：新增 Service.fixVersion，dictionaryId 可空；嵌入标准40～44定义，领域 ResolveDictionary 统一解析标准或 XML（根节点识别并验证显式版本）。应用统一 serviceDictionary 用于校验、表单、预览，运行时共享领域解析。Vue 用协议版本选择替代必选字典，直接保存新服务，之后独立添加消息；导入入口继续读取 XML 头并选择接口。旧绑定兼容、标准不落协议库。用空协议库 E2E 验证保存失败重试、持久化及真实FIX42收发，域/应用/运行时覆盖五版本，审查并打包带日期版本exe。

## Phase 10：请求独立调试与列式字段
1. 事件添加请求ID，运行时保留发送上下文并按FIX标识/序号匹配；TCP使用FIFO，另设会话记录及按范围清空。
2. 请求支持局部结构覆盖、描述及管理文本模式，统一预览/发送验证。
3. 文档/编辑/调试三个视图；定义编辑递归字段与组；调试单列字段、可展开组、较大文本编辑器。
4. 补充关联、结构/文本/解析测试和浏览器验收；完整差异审查，构建日期版本exe。

## Phase11：心跳可见性和原始报文切换
保留现有FIX心跳循环，状态模型返回运行情况及最后心跳时间。复用串行发送路径执行请求周期任务，快照绑定请求，现有脚本定时器兼容。UI提供周期控制和FIX心跳卡片；移除下方大编辑器，恢复单行预览，原始编辑使用生成值初始化并保留草稿。真实TCP/FIX测试、完整diff复审、日期包交付。

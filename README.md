# TcpConnect

本地 TCP / FIX 桌面调试工作台。Go + Vue 3，Wails 桌面窗口，按 DDD 划分通信、调试与 FIX 协议职责。参考 Apifox 的服务树、请求标签、脚本编辑与响应面板。

## 运行

Windows 可直接打开 `build/bin/TcpConnect.exe`。需要 Microsoft Edge WebView2 Runtime；当前开发机已安装。服务配置、请求、脚本、函数和字典默认保存在 `%APPDATA%/TcpConnect/workspace.db`，无需启动独立后端。

开发要求：Go 1.26+、Node.js 22+、npm、Wails v2.11；Windows 需要 GCC 与 WebView2。

```powershell
go install github.com/wailsapp/wails/v2/cmd/wails@v2.11.0
npm --prefix frontend ci
wails dev
```

生产构建：

```powershell
wails build -skipbindings
```

浏览器模式（与桌面使用同一应用层，只监听本机）：

```powershell
npm --prefix frontend run build
go run . --web --port 17839 --data-dir .local/dev
```

访问 `http://127.0.0.1:17839`。`--data-dir` 可在桌面或浏览器模式覆盖配置目录。浏览器模式与桌面可使用不同目录进行隔离测试。

## 通用 TCP

1. 左侧 `+` 新建 TCP 服务，配置地址和端口。
2. 选择接收规则：原始接收块、分隔符、定长、ASCII 长度头，或直接从下拉框的“自定义接收完成判断函数”分组选择已创建的函数。服务设置中可进入函数管理，新建或编辑后点击“绑定并返回服务设置”，最后保存服务并重新连接。
3. 添加请求，编辑 UTF-8 / HEX / Base64 报文，连接后发送。
4. 请求中设置前后置 JavaScript，以及请求、返回处理函数。
5. 下方查看收发、原始字节、脚本日志与定时任务。连接只在手动断开、对端关闭或协议错误时释放。

“每次收到数据即展示”保留 TCP 块边界，不能当成业务消息边界。分隔符模式包括分隔符；ASCII 长度头固定宽度、十进制、存储包体字节数，头本身不计入包体长度。

左侧搜索支持服务名、消息名和消息类型，忽略大小写及首尾空格。消息命中时仅显示匹配项并展开所在服务；服务名命中时显示其全部消息。清除搜索恢复完整列表，不改变已保存内容。

## FIX 协议

1. “协议”页或左侧 `+ → 导入 FIX XML` 选择 QuickFIX XML，支持 FIX 4.0、4.1、4.2、4.3、4.4。解析后先展示接口选择窗口，默认不勾选；搜索名称/消息类型，勾选如 `Logon (A)`、`NewOrderSingle (D)` 后点击“确认导入”，仅生成选中的命名模板。提供的 FIX44.xml 有 181 种可选消息。
2. 窗口支持“全选当前结果”和“清空选择”，跨搜索保留勾选；至少选一项才能确认。取消只读预览，不创建字典或服务。完整字典会在确认时保留，用于字段校验和响应解析。在服务设置中确认地址、SenderCompID、TargetCompID、心跳与登录选项，导入服务默认 `127.0.0.1:9878`。
3. 左侧点击消息即可打开字段、枚举、组件与嵌套重复组表单。新建 FIX 服务直接选择内置协议版本并保存，无需绑定或导入 XML，也不会弹出接口选择；保存后通过“新建请求”或“添加消息接口”按需添加消息。自定义 XML 可在协议库单独导入；服务右侧文档图标“补全消息模板”打开选择窗口，仅添加勾选的缺失类型，已有类型禁选，已有名称、字段值和脚本保持；`+` 可单独创建同类型的更多测试用例。
4. 完成必填字段后发送。默认自动生成 `8/9/35/34/49/52/56/10`；`8=BeginString` 使用选中的内置协议版本；自定义 XML 则使用根节点的版本（如 `<fix type="FIX" major="4" minor="2">` 对应 `8=FIX.4.2`）；`52` 使用 UTC（4.0/4.1 为秒，4.2 起为毫秒），`9/10` 按 UTF-8 字节计算。
5. 接收支持上述五种版本的分包、粘包，按 BodyLength 拆帧并校验 CheckSum；对端 BeginString 必须与当前连接选择的协议版本一致，版本不匹配会显示错误并断开。字段视图保留重复 Tag，并显示重复组路径和枚举含义。

内置 `assets/fixspec/FIX44.xml` 是本次提供的业务字典，181 种消息、26 个组件、1262 个字段，包含自定义业务消息。它仅用于首次初始化示例；以后导入的字典独立保存，不要求重新编译程序。

例如测试 FIX 4.2：导入 `assets/fixspec/FIX42.xml`，勾选需要的接口，配置服务地址及 Sender/Target，连接后发送 Logon。连接栏、接口选择窗口和预览会显示 `FIX.4.2`；订单、自动心跳、TestRequest 应答与重发都使用此版本。多个版本可以各建服务并存，无需修改程序或手动替换报文头。也可直接从左侧 `+ → FIX 协议服务` 选择内置 `FIX.4.2` 创建，不需要 XML 文件。更换已有服务字典后需重新连接；原始模式仍原样发送，适合异常测试。

自动登录按当前字典的 Logon 结构生成，只发送存在的字段。标准 FIX 4.2 没有 `553/554`，需认证时导入交易对手扩展过这些字段的字典；自定义必填字段请使用手动 Logon 表单。FIX 4.0/4.1 的旧式 CHAR 字符串、TIME/DATE 以及 4.2/4.3 的 UTCDATE/QUANTITY 字段已兼容。

FIX 5.x / FIXT 1.1 尚未实现传输字典与应用字典分离及 ApplVerID 协商，导入时明确拒绝。通用 TCP 仍可通过原始数据和脚本测试其他协议；此能力与 FIX 字典版本独立。

左侧服务和消息右侧的垃圾桶提供删除入口，确认后保存。删除服务会断开其连接、停止定时任务并删除所属消息；字典继续保留在协议库，需要单独删除。删除消息仅移除该用例。业务必填值仍需填写，模板不推测账号、订单等业务数据。

### 会话行为

- TCP 连接和 FIX 登录分别显示。服务可设置自动登录，也可手动发送 Logon 表单。
- 自动登录使用服务的心跳间隔，手动登录使用表单的 HeartBtInt；登录确认后使用对端返回的间隔维护心跳（支持 1～3600 秒），并回应 TestRequest（复制 TestReqID）。定时业务发送仍使用同一连接和序号。
- 发送序号与接收期望独立管理；接收缺口触发 ResendRequest。当前连接支持最近 1000 条、最多 16 MiB 发送历史的重发，管理消息以 GapFill 补齐。
- 每次新连接从序号 1 开始。此版本不提供跨重启的 FIX 序号与重发日志恢复，适用于本地联调；对端应使用匹配的重置策略。
- 勾选“原始报文”进入文本编辑，默认仍自动维护序号与头尾；另勾选“跳过自动计算（异常测试）”才按原样发送（除显式选中的请求处理函数外）。异常测试会影响正常会话，应另建测试连接。
- 字典声明的必填/类型/枚举自动校验；XML 未描述的业务条件、默认值和请求响应配对由用例及脚本补充。
- FIX 字段解析以 SOH 分隔，当前不支持 DATA 字段内嵌 SOH 的二进制扩展；通用 TCP 的 HEX/Base64 收发可保留任意字节。

## 脚本与数据

详见 [脚本 API](docs/scripting.md)。所有日志和异常在“脚本与事件”页显示。定时任务可单独停止，连接断开后全部自动停止。脚本为本机可信用户编写，在 Goja 中执行；不提供 Node.js、文件系统、任意 HTTP 或系统命令访问。执行超时是 CPU 保护，不是独立进程内存沙盒。

服务、处理函数的修改在重新连接后生效；请求内容与前后置脚本在下次发送时生效。配置手动保存，发送前自动保存。“另存用例”复制请求，修改名称后保存即可。导入工作区会替换当前配置，需要先断开所有连接。

凭据与脚本随工作区存储在本机 SQLite 中，导出 JSON 也包含这些配置；原始报文可含凭据。不会主动上传数据。收发历史仅保存在内存，最多 500 条且总载荷约 16 MiB；重启后清空，配置保持。

## 本机验收

```powershell
go run ./cmd/echo -port 9879
```

工具选择“本地 TCP / Echo 回显”，连接并发送即可。FIX 可使用内置模拟服务：

```powershell
go run ./cmd/fixmock -port 9878
```

选择“FIX 4.4 / 登录 Logon”，连接并发送，等待状态“FIX 已登录”。Sender 为 `FixClient`、Target 为 `Fix`。模拟服务接受订单并返回 NEW 状态回报，不执行真实交易。

### 当前 Windows 版本

本轮构建标识 `20261030.4`（窗口底部可见）。程序为 `build/bin/TcpConnect-20261030.4.exe`，避免与正在运行的旧文件混淆。关闭旧窗口后打开此文件，沿用本机原工作区。

XML 协议识别仅看根节点：`<fix major='4' type='FIX' servicepack='0' minor='2'>` 对应 FIX.4.2，minor='4' 对应 FIX.4.4。属性顺序、单/双引号和文件名不影响识别；导入选择窗口、协议库与发送预览展示解析出的版本。

### 请求文档、结构和调试

每个请求有“文档 / 编辑 / 调试”三个视图。文档展示当前协议和字段、必填及枚举；编辑可补充说明、增删字段和重复组、修改Tag/类型/枚举/必填及顺序。修改仅对当前请求生效，内置标准/XML原件保持；可恢复协议定义。字段改名迁移已有表单值，删除字段同步删除其值；修改Tag或类型后按新规则发送。删除必填字段也会改变此请求校验，请按对端实际协议设置。

调试字段为单列表格，每行一个字段，显示字段名、Tag、类型和值。每个作用域内必填项优先显示，同类保持原顺序；实际编码仍使用定义顺序。重复组及每条记录可展开/收起，支持添加、删除记录。“显示可选字段”展示其余字段。

表单下只显示单行报文预览。勾选“原始报文”或点击“编辑原始报文”，将表单生成值带入替换表单的编辑器，支持SOH或`|`分隔；默认仍按当前定义校验并重算序号、UTC时间、字节长度和校验和。取消勾选回到表单。未经手工修改的生成稿在再次进入时随表单更新；手工草稿保持，需覆盖时点击“从表单重新生成”。缺少必填值时明确提示，保留表单。扩展Tag请先在编辑视图定义；异常测试另勾选“跳过自动计算”。编辑器和响应区可拖高；鼠标位于编辑器内时，短报文直接滚动页面，长报文先在框内滚动，到顶/到底后继续滚动页面。历史记录可复制到编辑器后再发送，不修改历史原字节。

### 心跳与定时发送

“定时任务”页显示FIX自动心跳状态、实际协商间隔及最近发送时间；它在Logon成功后启动，按空闲间隔发送，并自动回复TestRequest。无需另建同类心跳任务。未登录时显示等待登录。

普通TCP心跳或周期业务报文可在同页设置1～3600秒并“启动定时发送”，不依赖后置脚本。首条在一个间隔后发送，沿用当前连接及启动时的请求快照，执行与手动发送相同的脚本和处理函数；FIX管理模式需先登录。修改内容后停止并重启任务。可单独停止，发送失败自动停止，断开清理，重连不自动恢复。请求周期任务与脚本定时器合计最多32个。

收发记录默认仅显示当前请求。FIX按ClOrdID/OrigClOrdID、OrderID、TestReqID、MDReqID等标识及RefSeqNum匹配，手动Logon/Logout按待响应同类型匹配；同一业务标识重复用于不同请求时优先归属最近发送者，因此请使用唯一业务请求ID。自动心跳、主动推送及未匹配数据在“会话记录”查看。普通TCP默认一次发送对应一帧完整响应，按发送顺序匹配；并发乱序、多帧响应及无标识推送无法据此准确归属，应结合接收完成规则和会话记录检查。

返回函数、后置脚本和脚本日志使用匹配请求发送时的上下文，定时任务保持创建请求的关联；未匹配推送不执行其他请求的后置脚本。清空仅作用于当前请求或当前服务的会话记录。FIX记录保存当时的有效字段定义，按实际35解码；重复Tag、未知字段和值中的`=`保留，未知项明确提示。更换请求定义不会重解释已有记录。历史为内存记录，连接重建不保留匹配队列，程序退出不持久化收发历史。

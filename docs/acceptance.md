# 手动验收

## TCP 工作台
1. 启动 `go run ./cmd/echo -port 9879`，打开工具。
2. 选择“本地 TCP / Echo 回显”，确认 localhost:9879，点击连接。
3. 发送默认报文，应出现一条发送与一条接收；可以重复发送，连接数保持 1。
4. 在前置脚本写 `return data.replace("Hello", "Hi")`，再次发送，原始发送与回显均为 Hi。
5. 在后置脚本写 `console.log("response",data)`，下方日志能直接看到输出。
6. 插入定时发送示例，发送一次后在定时任务中看到 heartbeat；等待周期数据出现，点击停止后停止发送。
7. 切换 HEX 请求，发送 `00 01 ff 80`；接收规则临时选原始接收块，HEX 视图应保持四个字节。
8. 断开连接，任务清空；重新打开程序，服务与脚本仍在。

## 三类函数
1. 函数页创建请求函数 `return data.replace(/\|/g,"\x01")`，在请求“处理设置”关联。
2. 创建返回函数 `return data.replace(/\x01/g,"|")`，发送后切换原始与处理后视图查看差异。
3. 在 TCP 服务设置中点击“管理接收判断函数”，创建函数 `const i=bytes.indexOf(10);return i<0?0:i+1`，点击“绑定并返回服务设置”。原服务名称、端口等草稿保持，接收规则直接显示该函数名称及已绑定提示；保存服务后重新连接。也可在接收规则的自定义函数分组直接选择，列表不包含请求/返回处理类函数。
4. 测试发送两条带换行消息，收到后按两帧展示；未带换行部分持续等待，连接关闭时提示未完成残包。
5. 写入 `while(true){}` 的前置脚本，约 1500ms 后可见超时；移除脚本后仍可发送。
6. 保存后刷新或重启，再进服务设置确认绑定函数名称保持；点击“编辑或更换绑定函数”应选中该函数。切换为内置规则会解除函数关联。

## FIX 字典与会话
1. 协议页能看到自带业务字典；选择 FIX44.xml 后先显示 181 种可选接口，默认未选、确认禁用。勾选 Logon (A)、NewOrderSingle (D) 并确认，应只创建两条命名消息，协议库仍显示完整 181 种消息及原字段/组件数量。需要全量时显式“全选当前结果”。
2. 打开导入服务设置，确认 Sender=FixClient、Target=Fix、localhost:9878。从协议库创建第二个 FIX 服务，保存时也需要选择接口，仅创建所选消息；取消选择应返回原服务配置草稿。
3. 启动 `go run ./cmd/fixmock -port 9878`。
4. 连接并发送 Logon，EncryptMethod=0、HeartBtInt=30、ResetSeqNumFlag=Y。状态应变为 FIX 已登录。
5. 等待心跳或手动 TestRequest，查看 34 递增、52 为 UTC，112 对应请求 ID。
6. NewOrderSingle 表单应体现业务字典要求：Account 必填，OutsideRth 为 8006；组件可展开、枚举显示说明、重复组可添加多行。
7. 填写 ClOrdID、Account、Instrument/Symbol、Side、TransactTime、OrderQtyData/OrderQty、OrdType，发送订单，模拟服务返回 ExecutionReport。
8. 选择 FIX 字段视图，能看到 Tag、名称、值和枚举解释；原始视图保留 SOH，处理后可显示 |。
9. 删除必填值时发送失败且窗口明确提示；原始模式允许手工异常测试，服务会话可能拒绝并关闭。

## 消息模板与删除

搜索验收：导入 FIX44.xml 并显式选择全部接口，收起服务后搜索 `  lOgOn  `，应自动展开并仅显示匹配的 Logon 消息；搜索服务名显示其全部消息，搜索 `1002re` 命中对应类型。无结果时显示“没有匹配的服务或消息”，点击“清除搜索”恢复列表。搜索中保存并重启，181 条消息保持，当前编辑内容不因过滤丢失。

1. 点击左侧 `NewOrderSingle (D)`，表单应为订单字段；打开其他消息应与 XML 定义匹配，而非统一显示 Logon。
2. 服务右侧 `+` 选择具体消息类型，创建后显示消息名与类型，支持同类型多个用例。
3. 修改某模板字段和脚本并保存，点击服务右侧文档图标“补全消息模板”，已有类型显示“已存在”并禁选，内容保持不变；勾选缺失类型确认，仅添加所选消息。
4. 左侧消息垃圾桶确认删除；删除另一条消息不改变当前正在编辑的消息。重启后仍已删除。
5. 服务垃圾桶确认删除，所属消息同步移除，连接和定时任务停止；其他服务保持。重启后已删服务不会重新出现，字典仍在协议库。
6. 自定义 XML 即使不定义 Logon，也应生成实际声明的消息、字段和组件表单；保存失败时删除目标仍保留并显示错误。
7. 接口选择窗口搜索后勾选消息，再换搜索词，已选计数保持；“全选当前结果”仅选当前匹配且不存在的类型，“清空选择”取消全部勾选。取消导入或无效 XML 不创建字典、服务或消息。模拟导入失败，窗口保留选择以便重试，重启后仍只有所选模板。
